====================================================================
WHAT WORKED
====================================================================

  - Conv1D over LSTM
      Sequence classification with short text (~30 tokens) favors local
      n-gram detection over long-range dependencies.
      Source: Goodfellow Ch 9 (CNN parameter sharing); Ch 10 RNN intro.

  - 254 filters, kernel 3
      Tuned via dev sweep. Kernel 3 catches bigrams/trigrams which
      contain most emotion cues in Reddit-style text.

  - BinaryCrossentropy + label_smoothing(0.05)
      BCE outputs concentrate near {0, 1} when threshold 0.5 is used as
      decision rule. Label smoothing prevents the model from pushing
      logits to ±infinity, which keeps probabilities well-distributed
      and stable.
      Source: Goodfellow Ch 7.5 noise robustness.

  - Output bias init from class priors
      Initializes sigmoid output to empirical prior so the model starts
      at the right marginal baseline; gradients can immediately learn
      discriminative features instead of correcting the 0.5-vs-prior offset.
      Source: Goodfellow Ch 8.4 Parameter Initialization Strategies.

  - Threshold 0.5 (default, untuned)
      With BCE + label smoothing the outputs are calibrated, so the
      natural sigmoid midpoint works without per-dataset tuning.
      Eliminates the highest-variance form of dev-set leakage.

  - 5-seed ensemble
      Single-model variance was high (~10 F1 points across seeds);
      averaging 5 stabilized at ~0.72.
      Source: Goodfellow §7.11 Bagging and Other Ensemble Methods;
      §7.12 Dropout (cites Szegedy 2014a recommending 5-10 model ensembles).

  - GaussianNoise(0.009) on embeddings
      Small input noise as regularization; tuned via sweep (peak at 0.009).
      Source: Goodfellow Ch 7.5 noise robustness.

  - SpatialDropout1D(0.3) after Conv1D
      Drops entire feature maps so adjacent positions can't leak signal.
      Better than regular Dropout for spatially-correlated conv features.

  - In-class word swap augmentation (variant of Wei & Zou 2019 EDA)
      Replaces a few words in rare-class examples with other words from
      the same class's training vocabulary. No external resources (no
      WordNet, no pretrained embeddings). Lifted F1 modestly on rare
      classes by distributing class-vocabulary signal across positions.
      Source: Wei, J. & Zou, K. (2019), arXiv:1901.11196.

  - Int-level duplication on truly rare classes
      Pure oversampling — each rare-class example shows up 5x in training.
      Anger came off 0.000 with this; annoyance/disapproval still stuck.

  - Adam + EarlyStopping(val_loss, patience=3, restore_best_weights)
      Default adaptive optimizer + standard implicit regularization.

  - L2(1e-4) / L2(1e-5) on embeddings:              0.696 / 0.715 (under baseline)

  - apply_class_balancing=True with alpha 0.25:     0.7111

  - Per-class threshold tuning:                     not attempted (overfit risk)
  - AdamW vs Adam:                                  0.7151 (tied, no benefit)


====================================================================
KEY RATIONALE — WHY SUB 4 OVER SUB 1
====================================================================

  - Sub 1 (focal + threshold 0.3) hit 0.7273 dev. Rejected because:
    * Focal loss with gamma=2 systematically produces lower-magnitude
      positive outputs due to the (1-p)^gamma down-weighting term, so
      threshold 0.5 misses many true positives. Required threshold 0.3,
      hand-tuned on dev.
    * Per-dataset threshold tuning is the highest-variance form of
      dev-set leakage — the optimal threshold may shift on test.
    * The decision rule was fragile under any test-set distribution shift.

  - Sub 4 (BCE + bias_init + threshold 0.5 + aug) hit 0.7218 dev.
    Trade-off: -0.0055 dev F1 in exchange for:
    * Calibrated probabilities (no per-dataset threshold tuning)
    * Robust 0.5 decision rule (dataset-independent)
    * Augmentation regularizes against rare-class memorization

    Net expectation: lower dev, comparable or higher test, much
    smaller variance under distribution shift.

  Key methodology lesson — getting the REAL F1 number BEFORE submitting:
    The training-time logged F1 (0.7218) was misleading by ~7 points.
    The reason: training-time metrics can be inflated by:
      1. Train+dev combined training (model "saw" dev during fit)
      2. Best-epoch metric (cherry-picks the high point of the loss curve)
      3. Tuned threshold that didn't make it into the saved model
      4. Different evaluation context than production inference

    The HONEST measure is to re-evaluate the saved checkpoint with the
    EXACT inference pipeline you'll use at test time. This was done in
    _check_dev_f1.py: load the saved .keras files via predict_test.py's
    pipeline, run them on dev.csv, compute F1 with threshold 0.5. That
    gave 0.6506, which predicted the eventual test F1 of 0.67 to within
    2 points.

    The training-time number (0.7218) over-predicted test by 5 points;
    the honest re-eval (0.6506) under-predicted by only 2 points.

  Workflow for any future ML project:

    1. Save the model checkpoint (vocab + weights + architecture)
    2. Write predict.py that produces submission/output from the
       checkpoint (no training, just inference)
    3. Write a parallel check.py that uses the SAME predict pipeline
       on the labeled dev set, reporting F1
    4. The check.py number is the trustworthy local proxy for test F1
    5. Do NOT trust the training-run F1 logs as a predictor of test
       performance - they are a development tool, not an evaluation

PROJECT CLOSURE (2026-04-29)
====================================================================

  Final placement: #8 of 15 on test leaderboard.
  Final test F1: 0.672 (training-time dev 0.7218, honest re-eval 0.6506).

  Methodology validated:
    - 3rd-tightest dev→test gap (-0.050) on the entire test board.
    - Top dev scorer (ilnurkhussainov, 0.923) and #2 (sanzhar, 0.826)
      both no-showed on test — strong indirect evidence that the
      pursue-pretrained-and-tune-hard track was overfitting.
    - rb (0.79 test, ~zero gap) is the model to study for "what does
      genuinely good generalization look like on this task."
    - The honest-local-re-eval workflow (0.6506 → predicted test 0.67)
      under-predicted by only 2 points; the training-time number (0.7218)
      over-predicted by 5 points. The check.py pattern is validated.

  Per-class predictions that held:
    - "anger came off 0.000 with augmentation" → confirmed on test (0.154).
    - "annoyance, disapproval stuck at 0.000 because vocab-level failure"
      → confirmed on test (both still 0.000).
    - This validates the diagnosis: rare-class augmentation rescues
      from-frequency failures but not from-vocabulary failures. Closing
      the last 2 zeros requires pretrained embeddings, not architecture.

  Outcome relative to constraint:
    - Project goal was course-techniques-only (no pretrained embeddings).
    - Final position (#8/15, 0.672 test) is within the predicted from-scratch
      ceiling (~0.72-0.73 dev → ~0.67 test) identified in KNOWN CEILING.
    - The model finished where the methodology said it would.

  Meta-lesson — match complexity to signal availability:

    Every architectural choice mattered. BatchNorm broke max-pool calibration.
    Stacked Conv1D didn't help. Multi-kernel parallel was worse than single.
    LayerNorm broke max-pool calibration in three positions. 10-seed ensemble
    was worse than 5. L2 on conv collapsed at 0.01, was under-baseline at 0.001.
    Focal loss forced threshold tuning which leaked dev. Sample weight inverse-
    frequency collapsed entirely.

    Each of these added capacity or constraint that had to be paid for in
    signal. The dataset (~30-token Reddit text, ~10K vocab, random-init
    embeddings) didn't have enough signal to pay. So the simplest viable
    configuration won — but only because the from-scratch constraint kept
    the representational ceiling low.

    The transferable framing: model complexity should match problem signal,
    not exceed it. "Simple wins" is the operational shortcut, but the
    transformer peer's higher ceiling (small layered transformer + attention
    pooling, scored above this project) shows simple isn't universal — they
    kept it simple too, but their architectural baseline had richer
    representations to start with. Their "simple" had a higher ceiling
    than this project's "simple."

    The actual skill is calibrating which case you're in. From-scratch
    constraint forced this calibration by exposing where added capacity
    stops paying. That's the durable lesson, separate from the score.

  Project status: CLOSED.
